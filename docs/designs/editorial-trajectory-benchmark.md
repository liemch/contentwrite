## Vision

### 10x Check

ContentWrite should not become another generic LLM eval runner. Its 10x research value is an
auditable editorial trajectory: a researcher can inspect which findings and revisions occurred,
whether aggregate remediation improved the initial draft, what the final quality/cost tradeoff
was, and where automated judgments disagreed with humans.

The first release remains a small pilot. Its 10-star quality comes from being harder to fool:
the protocol is locked before results, every aggregate can be recomputed offline, failed runs
remain visible, and internal gate scores are never presented as independent evidence.

```text
production workflow evidence
          │
          ▼
pure experiment kernel
  schemas / matching / reconciliation / statistics
          │
          ├──── Promptfoo adapter ──── case/judge orchestration + raw judgments
          │
          ├──── preregistration lock ─ protocol + dataset + code hashes
          │
          └──── offline verifier ───── integrity + deterministic recomputation
                                  │
                                  ▼
                         Markdown report + raw artifacts
```

### 12-Month Ideal

```text
reproducible three-arm pilot
      ↓
multiple independent judges
      ↓
isolated stage ablations
      ↓
cross-model editorial trajectory lab
```

The ideal lab compares models, workflow variants, domains, interventions, quality, cost, latency,
and human disagreement. Version 1 must move toward that future without building its matrices,
UI, or experimental workflow variants prematurely.

## Chosen Implementation Approach

**Pure experiment kernel + Promptfoo adapter**

Pure TypeScript modules own:

- JSON Schemas and canonical records;
- arm/pair matching;
- A/B order reconciliation;
- named denominators and failure flow;
- deterministic human-audit sampling;
- paired topic-level effects and exact inference;
- exploratory topic-blocked bootstrap analysis;
- deterministic source-grounding checks;
- report model and offline replay;
- preregistration lock validation;
- release artifact verification and independent headline-metric reference checks.

Promptfoo owns:

- dataset case and judge orchestration;
- judge-provider invocation and caching;
- raw pairwise judge calls;
- adapter-level result export.

Production `workflow.ts`, Prisma state transitions, and provider code remain the source of live
AI-TFES behavior. The kernel does not import Next.js routes or mutate workflow behavior.
A benchmark `WorkflowRuntime` exclusively owns generation/search calls, generation cache
identity, retries, budget checks, and usage capture for AI-TFES and matched-control candidates.
Promptfoo never invokes candidate-generation providers.
A benchmark-only trajectory adapter reads Prisma artifacts/transitions from the dedicated
database and converts them into canonical kernel records. Production behavior and state
transitions remain unchanged; benchmark-only adapters, explicit dependency seams, and
side-effect guards may be added outside the production request path.

### Trajectory adapter contract

Input:

- benchmark article ID, workflow run ID, expected protocol/run ID;
- read-only Prisma access to the dedicated benchmark database;
- expected artifact/transition schema versions.

Output:

- one canonical run record;
- ordered canonical step records linked to immutable artifact and transition IDs;
- initial/final artifact selection with explicit reasons;
- missing/duplicate/out-of-order provenance errors;
- no Article-column fallback when the corresponding immutable artifact is required.

The adapter never judges, reconciles, samples, or calculates report statistics.

## Accepted Scope

### Protocol preregistration lock

Before any confirmatory provider call, publish a GitHub preregistration release and an
append-only transparency-log attestation for its digest. The lock artifact contains:

- protocol and dataset version;
- topic/source/prompt/rubric hashes;
- generator and judge settings;
- endpoints, denominators, exclusions, retry policy, and schedule/sampling/analysis seeds;
- kernel and adapter git revision;
- expected release file list;
- success criteria and known limitations.

Any change after lock creates a new protocol version. The report lists deviations; it never
silently rewrites the lock.

Any pre-lock two-topic run is **exploratory only**. Its topics, outputs, labels, and results
cannot enter the locked confirmatory dataset or headline analysis. The lock is created before
the first evaluative run on confirmatory topics.

Confirmatory topic/source contents remain sealed and access-logged during implementation and
execution. The lock publishes their canonical hashes, selection rules, and licensing metadata,
not plaintext. Licensed contents are revealed with the verified result release. Development
uses synthetic fixtures and a separate exploratory dataset.

### Three-arm comparison contract

The preregistered primary comparison has three paired arms:

1. one-shot baseline using the frozen source packet, generator model, and generation settings;
2. AI-TFES using the same frozen packet/model and the production workflow path;
3. a minimal generic draft-then-revise control with no TFES gates or structured gate feedback,
   capped to the preregistered AI-TFES total output-token budget.

The lock defines exact prompts, transformations, token/call caps, pairing, exclusions, and
primary contrasts. Retrieval is not part of treatment: all three paired candidates receive the
same hashed source packet. Confirmatory execution remains concurrency 1, but a seeded,
preregistered schedule interleaves arm, case, and repetition order.

### Durable usage evidence

Every benchmark attempt writes typed usage/retry/call events to an append-only JSONL journal in
its staging directory. Required events are flushed at declared call boundaries. On completion,
the journal is atomically sealed into the attempt artifact. A crash freezes the partial journal;
the replacement attempt receives a new ID and never splices event streams.

### Versioned release contract

`release-contract-v1` defines:

- UTF-8 JSON serialized with JSON Canonicalization Scheme (RFC 8785);
- SHA-256 lowercase hexadecimal content hashes;
- POSIX `/` relative paths, no `..`, absolute paths, or symlink traversal;
- schema IDs and additive/breaking schema evolution rules;
- exact integer arithmetic for counts and declared decimal precision for derived rates;
- report numeric tolerance of `1e-12` for recomputed IEEE-754 values;
- a named deterministic PRNG algorithm and seed encoding for sampling/bootstrap;
- sort order for cases, pairs, artifacts, labels, and report rows;
- golden valid, corrupt-hash, missing-file, path-traversal, and numeric-drift fixtures.

No implementation chooses its own serialization, hashing, PRNG, or rounding convention.

### Offline artifact verifier

Provide one offline command that:

- validates release files against versioned schemas;
- checks declared hashes and referential links;
- checks expected/arm/matched/valid/unstable/invalid flow counts;
- reruns reconciliation, sampling, paired topic effects, exact inference, exploratory bootstrap,
  and aggregate report calculations;
- checks headline pair/count calculations against a separately implemented minimal reference
  calculator and hand-derived golden fixtures;
- fails nonzero on integrity or deterministic recomputation differences;
- performs no database, model, search, storage, or analytics calls.

The verifier and release layout share a versioned contract.

### Post-lock identity and deviation policy

- `protocol_id` is the SHA-256 hash of the canonical lock artifact.
- `run_id` is immutable and combines protocol ID, case ID, arm, repetition, and attempt.
- Transport reruns create a new attempt record linked to the prior attempt; they never replace it.
- Interrupted runs remain `INCOMPLETE` with last known step and named failure.
- Corrected metadata is append-only as a signed/hashed deviation record; raw files are immutable.
- A release missing required files is `INVALID_RELEASE` and cannot produce a headline report.
- Any post-lock protocol/dataset/rubric/analysis change creates a new protocol ID and separate run.

## CEO Review Constraints

- The report is pilot evidence over 10 topics × 3 repetitions × 3 arms, not population proof.
- The matched control equalizes the preregistered output-token cap, not total reasoning quality,
  latency, or dollar cost; all observed usage remains visible.
- Internal AI-TFES scores are diagnostics only.
- The judge uses a different model family and both A/B orders, but is not called independent
  evidence by model family alone.
- Deterministic checks report citation target validity, exact-quote/source-ID/hash integrity,
  broken references, and mechanically decidable claim-to-citation coverage separately.
- Two humans audit four locked-random and four diagnostic pairs; agreement remains descriptive.
- Benchmark execution uses a dedicated non-production database, runtime capability policy, and
  an OS/container sandbox with controlled mounts and default-deny egress through explicit
  provider/search proxies.
- Failed, unstable, invalid, and partial runs remain visible in fixed denominators.
- Production behavior and workflow state transitions remain unchanged.

   - Build a contract/fixture validator scaffold.
   - Gate: the scaffold rejects every corrupt contract fixture and accepts the golden fixture.
3. **Runtime, trajectory, and journal adapters**
   - Land the narrow `WorkflowRuntime`, exclusive candidate-generation ownership, read-only bulk
     trajectory adapter, atomic attempt journals, and production-default regression tests.
4. **Experiment contracts**
   - Implement three-arm matching, output-token-matched control, seeded interleaved schedule,
     fixed denominators, budget guards, deterministic grounding checks, and sealed dataset rules.
5. **Human-audit contract**
   - Implement label schema, blinded instructions, import validation, two-annotator
     disagreement representation, four-random/four-diagnostic sampling, and fixtures.
6. **Kernel reconciliation/statistics**
   - Implement reversed-order reconciliation, paired topic effects, exact inference,
     exploratory bootstrap, and report model from fixtures.
   - Gate: canonical JSON and deterministically formatted report text are byte-stable for golden
     fixtures. Internal floating-point recomputation uses the release contract's `1e-12`
     tolerance before deterministic report rounding.
7. **Offline verifier completion**
   - Validate release layout, hashes, schemas, references, counts, statistics, deviations, and
     independently implemented headline calculations.
8. **Exploratory two-topic pilot**
   - Use topics permanently excluded from confirmatory analysis.
   - Gate: verify three-arm execution, isolation, token/cost capture, judge parsing, grounding,
     and artifact completeness.
9. **Protocol lock and external attestation**
   - Freeze methodology, sealed dataset hashes, prompts, schedule, code/config hashes, and
     expected release layout.
   - Publish the GitHub preregistration release and transparency-log attestation before calls.
10. **Confirmatory full run**
   - Run the locked interleaved schedule, preserve failures, collect mixed human audit, reveal
     licensed dataset contents, verify release, then publish report.

If any go/no-go gate fails, do not hide incompatibility behind adapter complexity. Return to the
approach decision with evidence.

## Deep Review Decisions

### Architecture

1. Add a narrow typed `WorkflowRuntime` at `runWorkflowStep`. It contains only database
   access, text generation, search, clock/ID, `UsageCollector`, budget guard, and side-effect
   policy. Production defaults preserve current behavior. Helpers receive only capabilities
   they use, never the entire runtime bag.
2. `UsageCollector` emits append-only typed events for call start/success/failure, usage,
   retry, provider/model, run, step, and attempt. Production may use structured-log/no-op
   implementations; benchmark collection failure marks the attempt `TRACE_INCOMPLETE`.
3. Confirmatory execution has protocol concurrency fixed at 1 and follows a seeded,
   preregistered arm/case/repetition schedule with randomized interleaving.
4. Kernel code lives in `web/evals/` and may use only Node standard library plus its own
   domain modules. A source-level import-boundary test blocks Prisma, Promptfoo, Next,
   application aliases, environment, and network imports.
5. Attempt, pair, judgment, release, trace-eligibility, and deviation states use discriminated
   unions with exhaustive total functions.

```text
Promptfoo
   │ case schedule + raw judge calls
   ▼
benchmark adapter ──► WorkflowRuntime ──► production workflow/state machine
   │                    │                   │
   │                    └─ owns all candidate generation/search calls
   │                                        │
   │                               dedicated benchmark DB
   │                                        │
   └──────────────────────────────► artifacts + transitions + usage events
                                            │
                                            ▼
                                  trajectory adapter
                                            │ canonical records
                                            ▼
                                      pure kernel
                           ┌────────────────┼────────────────┐
                           ▼                ▼                ▼
                    protocol lock     Markdown report   verifier
                                                             │
                                             stage → verify → atomic rename
```

### Error and rescue policy

- Collector failure: preserve and sync the partial journal when possible, finish only the
  already-started external call, mark `TRACE_INCOMPLETE`, write a minimal fallback failure
  record, keep the attempt in failure denominators, and block it from publishable evidence.
- Release assembly: write under a same-filesystem staging directory, verify, then atomically
  rename to the immutable release path. Failed staging directories are quarantined.
- Process interruption: freeze the partial attempt as `INCOMPLETE`; restart with a fresh
  article/workflow/attempt ID. Never splice process segments in protocol v1.
- Judge malformed/empty/refusal: preserve raw output and classify `JUDGE_INVALID`; only
  named transport failures receive the frozen retry policy.
- Exact paired analysis with insufficient valid topics returns `NOT_ESTIMABLE`. Zero-valid
  exploratory bootstrap samples are discarded and counted.

### Security and data integrity

- Public serialization is schema allowlisted. Verifier runs secret/high-entropy/key-pattern
  scanning and blocks release; reviewed false-positive exceptions are append-only protocol
  deviations.
- Require `BENCHMARK_DATABASE_URL`, reject equality with runtime DB configuration, and verify
  a benchmark-only in-database marker handshake before any write.
- Source packets and candidate articles are structurally isolated as untrusted data in model
  prompts. Injection-like content is flagged and preserved, not silently stripped.
- Preserve raw source bytes privately. Model inputs use canonical UTF-8 NFC text with LF
  line endings, strict size/control-character rules, and SHA-256 hashes. Publish full sources
  only where licensing permits.
- Human annotation uses a separate blinded packet with opaque randomized candidate IDs and a
  sealed arm mapping. Labels lock before unsealing; verifier scans payloads for arm leakage.
- Confirmatory topic/source plaintext remains in a private, access-logged custody location until
  the run completes; development uses synthetic and permanently excluded exploratory material.
- The workflow runs under both typed runtime capabilities and an OS/container sandbox with
  controlled mounts and default-deny egress through explicit provider/search proxies.
- Case IDs must remain unique after Unicode normalization. Empty topic/source packets,
  disallowed control characters, duplicate IDs, and oversized fields fail before paid calls.

### Performance, tests, and deployment

- Trajectory export uses one read-only transaction with ordered bulk artifact and transition
  queries; no per-type/revision N+1 lookups. Versioned row/content caps reject pathological runs.
- Add `vitest.evals.config.ts`, `npm run eval:test`, and `npm run eval:coverage`; CI uses three
  parallel jobs: existing `quality`, offline `eval-offline` (`eval:test --coverage`), and
  `eval-integration` (PostgreSQL service plus Docker sandbox/broker system tests). PR wall-clock
  stays near `max(job)`, not `sum(job)`.
- Enforce 100% branch/function/line V8 coverage on `web/evals/**` and new/changed runtime
  modules; legacy untouched workflow code is not globally gated. Coverage exclusions require
  reviewed comments and fixture rationale.
- Protocol hard-caps provider calls and output tokens before each call. Currency cost uses a
  dated price snapshot and is labeled estimated when provider usage is missing.
- A per-attempt append-only journal flushes required usage events at declared boundaries and is
  atomically sealed; interruption/short-write tests prove partial evidence stays attributable.
- CI fails if `web/src` imports `web/evals`, Promptfoo, benchmark env/config, or release
  artifacts. Existing production build runs with no benchmark secrets or database.
- No migration or production activation is required. Rollback is a git revert of runtime seams
  and eval code; released research artifacts remain immutable.

### Retention

Every artifact is classified `PUBLIC`, `PRIVATE_RETAINED`, or `EPHEMERAL`. Private material
defaults to 90-day retention after release and may be explicitly extended. Deletion creates
an append-only tombstone so the report states when exact source replay is no longer possible.

## Test Strategy

```text
many unit/fixture tests
  schemas, canonicalization, unions, matching, reconciliation, denominators,
  schedule/PRNG/sampling, exact inference, exploratory bootstrap, grounding,
  reference calculations, secret/path rules, lock/deviation, report formatting
        │
        ▼
few offline integrations
  Promptfoo raw export/cache identity, release staging/verifier, blinded packet
        │
        ▼
few isolated DB/sandbox integrations
  DB marker, real state-machine with stub providers, durable journal,
  blocked egress/mounts, bulk trajectory export
        │
        ▼
manual protocol gates
  exploratory live pilot, protocol lock, confirmatory run, human audit
```

The Friday-at-2am test is an offline release replay that recomputes a byte-stable report from
golden raw artifacts while network and database access are denied. Hostile QA tests corrupt
every file/reference class. Chaos tests kill release assembly and workflow execution.

## Primary Estimand (protocol lock)

Frozen at preregistration; verifier rejects releases missing these fields.

- **Unit of analysis:** topic (case), not repetition or call.
- **Primary contrasts:** paired preferences on fixed three-arm contrasts declared in the
  protocol lock (one-shot vs AI-TFES, matched-control vs AI-TFES, one-shot vs matched-control).
- **Repetition handling:** average judge outcomes within topic before pairing; repetitions are
  not treated as independent samples in the primary analysis.
- **Tie policy:** ties excluded from the primary denominator and reported separately.
- **Primary inference:** exact paired test on the preregistered primary contrast; no optional
  stopping or post-hoc contrast selection.
- **Exploratory analysis:** topic-blocked bootstrap on the same aggregated pairs; labeled
  exploratory and never substituted for the primary result.
- **Multiplicity:** primary claim is the preregistered AI-TFES vs one-shot contrast; secondary
  contrasts are reported with explicit exploratory labeling.

## Outside Voice Amendments (Eng Review)

Accepted as protocol/verifier hardening (D21–D22):

1. **Token-matched control semantics:** matching uses the same preregistered maximum output-token
   cap for all arms at schedule time, not realized AI-TFES token counts. The control arm runs
   under that cap with the preregistered iterative policy; scheduling does not wait for AI-TFES
   completion.
2. **Journal reconciliation authority:** broker journal is authoritative for billable
   provider/search counts; child journal is authoritative for attempt-local ordering and
   timestamps; any call-ID mismatch or missing pair marks `TRACE_INCOMPLETE`.
3. **Trajectory immutability evidence:** trajectory export computes row/content hashes at export
   time; release verifier compares exported bundles to those hashes and flags post-export mutation.
4. **Frozen search arm equivalence:** all arms receive the same frozen source packet; only
   AI-TFES executes the search code path, which must return frozen responses keyed by query hash;
   baselines never receive retrieval-derived information beyond the shared packet.
5. **Provider fingerprints:** usage events capture provider endpoint, reported model/version
   metadata, and stable provider fingerprints when available; deviations after protocol lock are
   append-only protocol deviations.
6. **Licensing release classes:** each source is tagged `PUBLIC_REPLAYABLE` or
   `SUMMARY_ONLY`; the report states which verification claims remain possible when full source
   bytes cannot be distributed.
7. **Diagnostic human sample algorithm:** four diagnostic pairs are selected by a preregistered
   rule over automated flags (`UNSTABLE`, `TRACE_INCOMPLETE`, primary-contrast disagreement,
   grounding failure) computed before human packet generation; selection code is fixture-tested.

### Magical Moment and Quick Start Contract

Acceptance criteria:

### Distribution and Runtime Split

- Publish a reproducibly built single-file `benchmark-verify.mjs` with every release. TypeScript
  remains the source; CI rebuilds twice in clean environments and byte-compares outputs.
- Public verifier runs on Node 20+ and installs no dependencies.
- Full experiment runner uses the signed, digest-pinned Node-24 GHCR image with pinned Promptfoo.
- External preregistration/transparency attestation records verifier source commit, lockfile,
  build command, clean-build digests, and final SHA-256. `--self-check --expected <digest>`
  validates it offline.
- Verifier CI covers Linux, macOS, and Windows across supported Node majors, TTY/pipe/JSON
  output, spaces/Unicode paths, read-only directories, and blocked egress.
- Runner publishes linux/amd64 and linux/arm64. macOS Docker is supported. Windows runner is
  WSL2-only and non-confirmatory until the isolation suite passes there.

### CLI Contract

The public verifier is read-only. Experiment operations remain explicit operator scripts:
`benchmark:run`, `benchmark:lock`, `benchmark:publish`, and `benchmark:human-import`.

```text
node benchmark-verify.mjs [path]             # defaults to verify
node benchmark-verify.mjs verify [path]
node benchmark-verify.mjs inspect [path]
node benchmark-verify.mjs explain <error-code>
node benchmark-verify.mjs --self-check --expected <sha256>
node benchmark-verify.mjs --version
```

- Omitting the path auto-detects exactly one release manifest in the current directory.
  Zero or multiple manifests produce an actionable ambiguity error.
- TTY output is human-readable and may use color; piped output is stable plain text.
- `--json` emits canonical, versioned JSON.
- CLI SemVer and integer release-contract versions evolve independently.
- Latest verifier supports contract N and N−1. Older contracts return
  `E_SCHEMA_UNSUPPORTED` with the exact compatible verifier URL and digest.
- Every release keeps its exact verifier; published research bundles are never rewritten.

### Error and Diagnostics Contract

`release-contract-v1` includes the success/error JSON envelope, semantic exit mapping,
severity, stable error ordering, primary-error precedence, safe path rules, truncation,
redaction, and golden CLI fixtures.

| Exit | Meaning |
|------|---------|
| 0 | Verification completed with declared verdict |
| 1 | Integrity or recomputed result mismatch |
| 2 | Malformed or unsupported input |
| 3 | Verifier environment, self-check, or internal failure |

Every human error starts with a stable code and includes what happened, why it matters, safe
actual/expected values, the exact next action, and a documentation link. `--json` exposes the
same information in stable fields. Golden fixtures cover single/multiple failures,
TTY/plain/JSON, diagnostics, and all exit statuses.

`--diagnostics <file>` writes only allowlisted metadata: verifier version/digest, platform,
Node version, contract/protocol ID, stage timings, error codes, and redacted relative paths.
It excludes source text, credentials, provider configuration, absolute home paths, and raw
stacks. Errors link to the verifier-discrepancy issue form.

### Verification Capability Classes

- `PUBLIC_REPLAYABLE`: all integrity, statistics, and source-grounding checks run.
- `SUMMARY_ONLY`: source-dependent checks are `NOT_REPRODUCIBLE`, never pass/skipped silently.
  The overall result is `VERIFIED_WITH_LIMITATIONS`; human/JSON output enumerates verified and
  unavailable claims. Headline text cannot imply full grounding replay.
